# Единый каркас ohrana.tech

Цель: перестать редактировать десятки самостоятельных HTML-страниц вручную, сохранив текущие URL и готовый статический HTML для поисковых систем и AI-поиска.

## Главный принцип дизайна

**Главная `/index.html` — единственный визуальный эталон сайта.**

- Новый шаблон не вводит отдельную тему или новый дизайн.
- Цвета, Cormorant/Manrope, размеры секций, кнопки, карточки, золотые линии, hover/reveal-анимации, шапка, футер, чат и мобильная панель должны повторять паттерны главной.
- Снимок эталона хранится в `site-src/reference/home-design.source.html` для сравнения при рефакторинге.
- Уникальные страницы могут иметь собственную композицию контента, но не собственную дизайн-систему.
- При конфликте старой страницы с главной приоритет у визуальных правил главной; смысл и уникальный контент страницы сохраняются.

## Принцип сборки

- `site.json` — единые данные компании: телефон, email, лицензия, реквизиты, Метрика, Formspree.
- `pricing.json` — единый источник подтверждённых стартовых цен и соответствий «тип объекта → услуга».
- `partials/` — общие блоки сайта: head, сущность организации, шапка, футер, навигация, мобильная панель, чат.
- `layouts/` — каркасы типов страниц: услуга, объект, статья, регион.
- `pages/` — уникальные данные и контент каждой страницы.
- `assets/` — единые CSS и JS вместо больших повторяющихся `<style>`/`<script>`.
- сборка генерирует обычные `index.html` в существующие URL, поэтому поисковик и AI-краулер получают готовый HTML без клиентской подстановки.

## Правила миграции

1. Не менять существующие URL без отдельной причины и редиректа.
2. Контент существующей страницы переносить 1:1, если отдельно не согласовано редактирование текста.
3. Не менять рабочую форму Formspree и её имена полей без явной задачи.
4. Главную не переделывать в ходе миграции — она служит визуальным референсом.
5. Сначала мигрировать одну тестовую объектную страницу (`/ohrana-skladov/`) и проверить HTML/визуал.
6. Затем переносить однотипные страницы группами.
7. Любая цена, которая повторяется на нескольких страницах, должна браться из `pricing.json`, а не вводиться вручную повторно.
8. Если стартовая цена не подтверждена текущим контентом, показывать «Индивидуальный расчёт», а не придумывать цифру.

## Поиск и AI

- Все ключевые факты должны быть в видимом HTML, а не только в JavaScript.
- Каждая коммерческая страница должна иметь уникальные title, description, canonical и H1.
- Услуга описывается структурированными данными `Service`, а поставщик ссылается на одну сущность организации `https://ohrana.tech/#organization`.
- FAQ в JSON-LD должен соответствовать видимому FAQ.
- `robots.txt` разрешает публичный контент поисковым и AI-search краулерам; `site-src/` закрыт от индексации.
- `llms.txt` служит дополнительной навигационной картой, но не заменяет качественный HTML, sitemap и структурированные данные.

## Рекомендуемые типы шаблонов

- `service` — физическая, пультовая, техническая охрана, сопровождение грузов.
- `object` — склады, офисы, ТЦ, магазины и другие объекты.
- `region` — Москва/МО и региональные страницы.
- `article` — материалы в `/stati/`.
- `special` — цены, контакты, договор, коммерческое предложение.

## Что это даст

Изменение телефона, меню, футера, Метрики, общих SEO/AI-элементов, тарифов или дизайна выполняется в одном месте. При этом каждая страница сохраняет собственную поисковую задачу, H1, метаданные, JSON-LD и уникальный текст.
